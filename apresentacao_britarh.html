Visão Geral: Arquitetura Limpa Clean Arch

O ecossistema do BritaRH é estruturado com base no desacoplamento de responsabilidades, garantindo facilidade de manutenção e testabilidade.

As camadas são rigorosamente definidas de forma que a lógica de negócios central permaneça imune a mudanças tecnológicas (banco de dados, frameworks, UI).

A Regra da Dependência

Dependências de código apontam apenas para dentro. O Domínio não conhece a Infraestrutura nem o Banco. A Apresentação consome a Aplicação, que consome o Domínio.

Fluxo de Camadas

  • Domínio: Regras críticas e fundamentais do negócio.
  • Aplicação (Casos de Uso): Fluxos e orquestrações de dados.
  • Infraestrutura: Adaptadores de banco (SQLAlchemy), gateways (MinIO), HTTP.
  • Apresentação: Componentes visuais Next.js, hooks customizados e views.

Domínio: Entidades & Value Objects Domínio

A camada de Domínio representa as regras de verdade conceitual da plataforma. É modelada com objetos puros do Python, livre de frameworks de persistência ORM.

  • Entidade: Objeto com identidade única através do tempo.
    Ex: O objeto Job (Vaga) possui ID único (UUID), estado e invariantes internas.
  • Value Object: Objeto imutável definido unicamente por seus atributos.
    Ex: CPF e Email com validação estrutural no construtor.
backend/app/domain/entities.py
@dataclass
class Job:
    title: str
    area: str
    status: JobStatus = JobStatus.OPEN
    questions: List[Question] = field(default_factory=list)
    id: uuid.UUID = field(default_factory=uuid.uuid4)
    
    def close(self):
        self.status = JobStatus.CLOSED
        
    def can_modify_questions(self, has_applicants: bool) -> bool:
        # Invariante: não altera questões se houver candidatos
        return not has_applicants
backend/app/domain/value_objects.py
@dataclass(frozen=True)
class CPF:
    value: str
    
    def __post_init__(self):
        clean = "".join(filter(str.isdigit, self.value))
        if len(clean) != 11:
            raise ValueError("CPF inválido")
        object.__setattr__(self, 'value', clean)
        
    def formatted(self) -> str:
        return f"{self.value[:3]}.{self.value[3:6]}..."

Domínio: Erros & Repositórios (Contratos) Domínio

Para blindar as regras de negócios de contaminações externas, o Domínio define suas próprias **Exceções** e **Contratos de Persistência** (Interfaces de Repositório).

  • Erros de Domínio: Exceções específicas que impedem regras inválidas no negócio. Lançadas pela Entidade ou Caso de Uso e convertidas na camada HTTP em códigos apropriados.
  • Interfaces (Portas): Classes abstratas (`IJobRepository`) que declaram os métodos necessários, sem vazamento de detalhes técnicos como SQL ou sessões de banco.
backend/app/domain/exceptions.py
class DomainException(Exception):
    """Base para todos os erros de negócio"""
    pass

class JobClosedException(DomainException):
    def __init__(self, job_id: uuid.UUID):
        super().__init__(f"A vaga {job_id} está fechada e não aceita candidaturas.")

class AlreadyAppliedException(DomainException):
    def __init__(self, email: str):
        super().__init__(f"O email {email} já está inscrito nesta vaga.")
backend/app/domain/interfaces.py
from abc import ABC, abstractmethod

class IJobRepository(ABC):
    @abstractmethod
    async def create(self, job: Job) -> Job: pass

    @abstractmethod
    async def get_by_id(self, job_id: uuid.UUID) -> Optional[Job]: pass

    @abstractmethod
    async def update(self, job: Job) -> Job: pass

Aplicação: Casos de Uso (Use Cases) Aplicação

A camada de **Aplicação** orquestra o fluxo de dados vindos da parte de fora e direciona a execução das regras de negócio.

  • Independência: O Caso de Uso depende apenas das portas/interfaces e entidades do Domínio.
  • Responsabilidade Única: Cada classe executa uma ação de negócio discreta (ex: `CreateJobUseCase`).
  • Transações: Coordena operações atômicas envolvendo múltiplos repositórios.
backend/app/usecases/job_usecases.py
class CreateJobUseCase:
    def __init__(self, job_repository: IJobRepository):
        self.job_repository = job_repository

    async def execute(self, job_in: JobCreate) -> DomainJob:
        # Instancia e constrói a entidade pura
        domain_job = DomainJob(
            title=job_in.title,
            area=job_in.area,
            description=job_in.description,
        )
        # Adiciona as questões encapsuladas
        for q in job_in.questions:
            domain_job.add_question(
                DomainQuestion(text=q.text, options=q.options, correct_index=q.correct_index)
            )
        # Persiste através da abstração (repo)
        return await self.job_repository.create(domain_job)
backend/app/usecases/job_usecases.py
class UpdateJobQuestionsUseCase:
    def __init__(self, job_repo: IJobRepository, app_repo: IApplicationRepository):
        self.job_repo = job_repo
        self.app_repo = app_repo

    async def execute(self, job_id: UUID, questions: List[QuestionIn]) -> DomainJob:
        job = await self.job_repo.get_by_id(job_id)
        if not job: raise JobNotFoundException()
        
        # Verifica invariantes antes de alterar
        has_applicants = await self.app_repo.count_by_job_id(job_id) > 0
        if not job.can_modify_questions(has_applicants):
            raise DomainException("Já existem candidatos para esta vaga.")
            
        # Executa modificações e salva
        job.update_questions(questions)
        return await self.job_repo.update(job)

Infraestrutura: HTTP & Injeção de Dependências Infra

A camada de **Infraestrutura** conecta os detalhes do mundo externo (frameworks, libs, conexões físicas) com as regras de negócio puras da aplicação.

  • Framework HTTP: FastAPI atua como controlador de borda, mapeando rotas REST, realizando validações Pydantic e gerindo erros globais.
  • Injeção de Dependências (DI): Implementado através de `Depends` do FastAPI, instanciando os adaptadores concretos e injetando nos Casos de Uso.
backend/app/api/v1/jobs.py
@router.post("/", response_model=JobRead)
async def create_job(
    job_in: JobCreate,
    usecase: CreateJobUseCase = Depends(get_create_job_usecase)
):
    try:
        # Executa o caso de uso injetado dinamicamente
        return await usecase.execute(job_in)
    except DomainException as e:
        raise HTTPException(status_code=422, detail=str(e))
backend/app/api/deps.py
async def get_job_repository(
    db: Annotated[AsyncSession, Depends(get_db)]
) -> JobRepository:
    return JobRepository(db) # Injeta sessão assíncrona do SQL

async def get_create_job_usecase(
    repo: Annotated[JobRepository, Depends(get_job_repository)]
) -> CreateJobUseCase:
    return CreateJobUseCase(repo) # Injeta repositório no Caso de Uso

Infraestrutura: Repositórios & Storage Infra

A persistência de dados e o armazenamento de objetos binários são implementados através de gateways concretos na infraestrutura.

  • Persistência ORM: SQLAlchemy assíncrono. Mapeia dados físicos e converte para entidades puras de domínio no retorno.
  • Storage (MinIO / S3): Gerenciamento de arquivos e PDFs de currículos em nuvem privada, gerando URLs assinadas temporárias para segurança.
backend/app/adapters/repositories/job_repository.py
class JobRepository(IJobRepository):
    def __init__(self, session: AsyncSession):
        self.session = session
        
    async def get_by_id(self, job_id: uuid.UUID) -> Optional[DomainJob]:
        stmt = select(ModelJob).options(selectinload(ModelJob.questions)).where(
            ModelJob.id == job_id,
            ModelJob.deleted_at.is_(None)
        )
        result = await self.session.execute(stmt)
        model = result.scalar_one_or_none()
        if not model: return None
        return self._to_domain(model) # Mapeia DB -> Domínio
backend/app/services/storage.py
class MinioStorageService(IStorageGateway):
    def upload_file(self, content: bytes, filename: str, content_type: str) -> str:
        # Conecta ao cliente S3/MinIO e realiza o upload seguro
        self.client.put_object(
            self.bucket_name,
            object_name=filename,
            data=io.BytesIO(content),
            length=len(content),
            content_type=content_type
        )
        return f"https://{self.endpoint}/{self.bucket_name}/{filename}"

Apresentação: Componentes & Interface Frontend

A interface do **BritaRH** é desenvolvida com **Next.js (App Router)** e estilizada com **Tailwind CSS**. A camada de apresentação é focada em usabilidade e interatividade fluida.

  • Client Components ("use client"): Componentes que gerenciam interações complexas do DOM, como o editor interativo de testes do recrutador.
  • QuestionBuilder: Componente reativo encarregado de gerenciar dinamicamente formulários de questões, verificando as regras mínimas (5) e máximas (20) diretamente no cliente.
frontend/src/components/QuestionBuilder.tsx

  const [questions, setQuestions] = useState<Question[]>([]);
  const [error, setError] = useState(false);

  const addQuestion = () => {

    setQuestions([...questions, emptyQuestion()]);
  };

  const handleSubmit = () => {
    if (questions.length < 5) {
      setError(true);
      return;
    }
    onSubmit(questions);
  };
  
  // Renderização dos blocos e inputs...
}

Apresentação: Hooks Customizados Frontend

Os **Hooks Customizados** do React servem para encapsular a lógica de estado, chamadas externas de API e validação, separando a lógica de negócios visual da estrutura HTML.

  • useAuth: Encapsula o controle de acesso JWT, o login e a diferenciação de perfis (Candidato vs Recrutador - RBAC) via cookies/NextAuth.
  • useJobMutation: Abstrai o ciclo de vida de requisição HTTP (loading, error, success) para salvar ou modificar vagas, isolando chamadas assíncronas do Axios/Fetch.
frontend/src/hooks/useJobMutation.ts
export function useJobMutation() {
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  const createJob = async (data: JobInput) => {
    setLoading(true); setError(null);
    try {
      const response = await apiClient.post("/jobs", data);
      return response.data;
    } catch (err: any) {
      setError(err.response?.data?.detail || "Erro ao criar vaga");
      throw err;
    } finally {
      setLoading(false);
    }
  };
  return { createJob, loading, error };
}

Qualidade: Testes Unitários Garantia de Qualidade

Testes Unitários garantem a estabilidade de regras de lógica puras. São executados de forma isolada, rápida e sem necessidade de infraestrutura de banco de dados ou redes.

  • Backend (Pytest): Focado em validar as invariantes e métodos das entidades de domínio, como limites de notas ou formatação estrutural de e-mails e CPFs.
  • Frontend (Vitest): Validação ágil de utilitários locais, máscaras, normalizadores e fluxos isolados no cliente TypeScript.
